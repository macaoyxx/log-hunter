## 目标（为什么做）

v0.4.0 后实测 AI 设置里给模型勾选「视觉」并保存，重开设置后勾选消失（复现：`GLM-5.3-Flash`，窗口/上限留空）。根因：`SetAiConfig` 保存时把「窗口/上限均为 0」当作新增条目，按模型名重算能力并覆盖 `Vision`；而 v0.3.1 起 UI 刻意让这两个数字留空，留空条目每次保存都被写回能力表的判定。同一条件还导致含 vl/vision 关键词的留空模型取消不了视觉、命中能力表的留空模型首次保存丢勾选。

## 范围（做了什么，清单）

- **修复**：保存不再改写能力字段——预填只在条目诞生时发生一次（拉取到新名 / 手填名敲定），之后条目完全归用户
- **修复**：数字输入框清空后保存被拒——`v-model.number` 清空留下空串，Go 侧 int 反序列化报错整次保存被拒；清空统一归一为留空（= 用默认）；保存报错可悬停看全文
- **修复**：视觉通道厂商/模型级联——模型下拉只列所选视觉厂商的视觉模型；切换厂商时不在新厂商视觉列表里的值一律清空；取消勾选、删行后已选值失效即清空
- **保护**：存量悬空视觉模型——视觉通道指向未勾视觉的条目时（旧版保存 bug 的遗留，中转一直可用），打开设置不再被改掉；下拉兜底选项按实际情况标注「未勾视觉」或「不在该厂商」
- **修复**：删模型行/切主厂商后的主模型引用自愈
- **修复**：打开设置瞬间的重拉结果不再覆盖刚做的编辑；草稿已有编辑时，没动过的授权目录仍单独跟随后端最新
- **修复**：新增行空名提交不再消耗一次性预填；预填失败进错误红条不再静默
- **测试**：引入前端测试运行器（Vitest + happy-dom，`cd frontend && npm test`，并经 `prebuild` 接入 `npm run build`）与设置页回归用例 18 条；绑定层 `SetAiConfig` 保存路径单测（此前路由用例直接写 store，绕过了保存路径）
- **工程**：`frontend/.npmrc` 把本项目的 npm 源固定为公共镜像；`frontend/package-lock.json` 改为留本地不入库
- **文档**：`AGENTS.md` 架构树补 `internal/ai/` 与 `ai.go`、常用命令补 `go test .` 与 `npm test`、补充 npm 公共源与前端单测约定；`main.go` 注释里的发版脚本名订正
- **沉淀**：`.memory/ai-config.md`——保存路径不得按零值判「新增」重算能力字段；预填只在条目诞生时发生一次；设置页自愈逻辑区分用户动作与加载重算；前端测试写法与不引 `@vue/test-utils` 的原因；并入 README 记忆导航
