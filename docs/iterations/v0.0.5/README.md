## 目标（为什么做）
①无条件全览（刚拖入默认视图）被 200 万条上限截断——2GB 日志只能看前 200 万行，根因是全览把每行物化进结果数组（64B/条）；②固定 200 万上限对大内存机器太保守（用户反馈）；③「检查更新」只跳浏览器手动下载覆盖，免安装单文件 exe 的更新体验割裂（用户反馈）；④启动偶发慢「点击半天才起来」（用户反馈，规律不明）。

## 范围（做了什么，清单）
- **全览零物化**：纯全览（无文本+无时间+无级别+平铺）改纯索引视图——不物化结果数组，Total=Σ行数、永不截断、额外内存≈0；GetResults 按窗口从行索引翻译取行；级别统计/最长行扫索引计算（口径与物化路径一致）
- **结果上限内存自适应**：物理内存×25%÷64B/条，下限 200 万保底、封顶 2000 万（16GB≈2000 万条）；QueryStats 上报实际上限，截断提示动态化
- **流式导出**：导出改分批读行写盘，全览与查询模式统一（不再全量 fullText 常驻内存）
- **应用内自动更新**：检查更新解析 Release 资产 → 确认浮层 → 下载（进度条）→ sha256 校验（历史版本无 checksum 过渡兼容）→ 解压 → rename 自替换 → 「立即重启/稍后」选择；修复 dev 版本判断失效 bug
- **启动优化**：StartHidden + 前端就绪 WindowShow 消除空窗期（Go 侧 3s 兜底）；启动耗时埋点写 data/startup.log（进程→OnStartup→界面就绪）；README 补 Defender 排除项指引（未签名 exe 被实时扫描是启动慢头号嫌疑）
- **发版链路**：package.sh 生成 zip 的 sha256，Release 附带校验文件
- 边界（用户定）：跨段「点击继续」按钮保持现状；文件关联（右键打开方式）本迭代不做

## 影响面
- `QueryStats` 新增 `resultLimit` 字段、`UpdateInfo` 新增资产字段、新增绑定 `SetMerged`（v0.0.4）/`StartUpdate`/`Restart`/`CopyText`/`CopyLineText`/`GetLineText`/`ReportStartupReady`/`LastStartupCost`，前端绑定随 wailsjs 再生成（已同步）
- **行为变化**：无条件全览不再截断（原 200 万条上限）；带条件查询上限按物理内存自适应（200 万~2000 万）；时间过滤自 v0.0.4 起按锚点继承包含无时间行；剪贴板全部改后端直写；上下文/复制内容不再 64KB 截断（显示层仍截断）
- Release 附带 `.sha256` 校验文件（自动更新强制校验；历史版本无校验文件过渡跳过）
