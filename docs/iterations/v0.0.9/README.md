## 目标（为什么做）
用户实测：启动后立刻点「从电脑选择」，文件对话框弹出即整个程序闪退；等一会儿再点正常。两轮终端捕获崩溃日志实锤根因（WebView2 Focus 致命错栈）：启动 3 秒兜底 WindowShow 无条件执行，SetForegroundWindow 把主窗口拉前台，焦点消息进入刚弹出的系统模态对话框期，Chromium.Focus 报「The parameter is incorrect」，Wails 错误回调直接 Fatal 退出进程。

## 范围（做了什么，清单）
- **showWindowOnce 统一显示入口**：CAS 防重（全仓唯一 WindowShow 调用点）+ 显示发起后 300ms 焦点消息消化期再置「稳定」标记
- **3 秒兜底条件化**：仅当前端从未发起显示（前端真异常）时动作——正常启动后绝无多余的窗口操作
- **对话框守卫**：PickFiles / SaveFileDialog 弹系统对话框前 waitWindowShown 等待稳定标记（50ms 轮询、4s 上限由兜底补位）——窗口显示在途与模态对话框时序上不可能重叠

## 影响面
仅 app.go 启动/对话框时序；启动埋点、自动更新重启显示、正常对话框行为不变。

## 结果
- go test 三包全绿 + wails build；pr-review 98/100（能合）

- 排查过程沉淀：GUI 时序竞态类 bug 以终端启动捕获 stderr + 崩溃栈定位（双击启动看不到任何输出）；一次 python 批量替换静默失败的教训——修复必须 grep 验证落盘
