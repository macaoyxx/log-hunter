# LogHunter — 本地大日志快速排查工具

拖拽多个日志文件（支持 GB 级），用关键字 / 正则 / 时间范围 / 级别组合查询快速定位问题。
纯本地运行，索引全内存、不落盘：**用完一键清空，随时换下一批日志，零残留**。

## 功能

### 加载与识别
- **拖拽加载**：一次拖入多个文件（或系统对话框选择），自动识别格式与编码
- **格式自动探测**：常见文本格式（`2024-01-15 10:23:45.123 ERROR`、`[时间] [级别]`、`时间 [] [线程 ][INFO][文件]`（AgileBPM 等空格毫秒+方括号级别格式）、级别前置、syslog、httpd）、JSON Lines（timestamp/level 字段）、GBK 编码自动转码；探测采用头/中/尾跨区采样，局部特殊段（如大段 SQL）不会导致误判；识别不出时关键字查询不受影响

### 查询
- **组合查询**：多关键字（AND/OR 可切）、排除词、正则（Go RE2，任意输入不会灾难性回溯）、时间范围（自绘日历选择器 + 「最后5分钟/30分钟/1小时/当天」快捷段）、日志级别多选
- **筛选链**：生效条件以胶囊链展示在搜索框下，点 × 移除并立即重查，排障"逐步缩小包围圈"可回退
- **正则模板库**：不会写正则可直接选常用模板（IP/URL/异常堆栈/耗时/手机号/GUID/中文报错/SQL 等），附写法速查小抄
- **查询历史**：搜索框左侧 🔍▾ 图标下拉，最近 20 条一键重跑；「清空重来」连同查询条件一并重置

### 结果浏览
- **命中高亮**：结果与上下文里命中的关键字/正则片段琥珀色标记（分段渲染防 HTML 注入）
- **全文显示**：日志行多长显示多长（64KB 防御上限），单行展示、左右横向滚动查看全文；带列表头
- **百万结果流畅滚动**：虚拟滚动 + 超大数据集分段续载
- **逐条导航**：`◀ 上一条 | 第 N / 总数 条 | 下一条 ▶`，跳转/键盘 ↑↓/点击行数字跟随当前条
- **选中行醒目**：琥珀底色 + 左侧指示条 + 描边 + 行号高亮，横向滚动到远处也能定位
- **级别分布统计**：结果条显示各级别命中数（如 ERROR 12 · WARN 30），点击即按该级别过滤重查
- **上下文详情**：双击行右侧滑出面板，前后行数可调；点击任意行把视角移过去，**目标行自动滚到视口中央**；可**复制本行**或**复制全部上下文**（纯原文，直接贴给别人）
- **导出**：TXT（仅原文行）/ CSV（文件,行号,时间,级别,内容）
- **进度与取消**：索引/查询实时进度，长操作可随时取消

## 性能（1GB 混合格式日志实测，NVMe / 8 核）

| 操作 | 耗时 |
|------|------|
| 加载 + 建索引 | ~1.4 s |
| 关键字查询（命中 104 万条） | ~0.4 s |
| 正则查询（命中 44 万条） | ~0.4 s |
| 时间范围过滤（索引直查） | ~10 ms |
| 时间 + 关键字组合 | ~10 ms |
| 级别过滤（命中 126 万条） | ~0.2 s |
| 双击看上下文（前后各 50 行） | <1 ms |

内存占用：行索引约 120 MB / GB 日志；查询结果只存偏移，预览按窗口惰性生成。

## 架构

```
internal/logscan/          核心引擎（纯库，无 UI 依赖）
├── detect.go    格式探测（内置模板 + JSON 行），探测期锁定时间戳 layout，
│                空格毫秒规范化（AgileBPM），级别有效命中双分制优选
├── encoding.go  GBK/UTF-8 探测与转码（关键字按文件编码匹配）
├── lines.go     分块并行读（16MB 块、边界对齐换行）、缓冲池、顺序读游标
├── indexer.go   内存行索引：每行 偏移/时间戳/级别 平行数组
├── matcher.go   文本匹配器：包含词/排除词/正则按编码预转换
├── scanner.go   全文件并行扫描（只收集偏移与行长，不做结果构建）
├── query 路径   时间/级别条件 → 内存索引筛候选 → 候选行文本匹配；
│                无时间条件 → 并行全扫；预览延迟到结果窗口生成
├── context.go   上下文读取（窗口倍增法定位前后 N 行）
└── session.go   会话管理：文件增删/一键清空/查询执行/级别统计/导出
app.go                     Wails 绑定层（进度事件、对话框）
frontend/src/              Vue 3 界面
├── App.vue                布局与联动（清空重置/级别点击/高亮词传递）
├── QueryBar.vue           搜索框+筛选链+高级条件+正则模板库+历史+时间快捷段
├── ResultTable.vue        表头+单行横向滚动+虚拟滚动+分段+逐条导航+级别统计条
├── ContextPanel.vue       右侧上下文面板（全文、高亮、复制本行/全部、目标居中）
├── HighlightText.vue      分段高亮组件（防 HTML 注入）
└── TimePicker.vue         自绘日期时间选择器
cmd/logscan-bench/         性能验收基准（生成 1GB 混合日志并计时）
tools/genicon/             应用图标生成（SDF 绘制 → PNG/ICO）
```

设计要点（为什么快）：

1. **元数据索引而非全文索引**——时间/级别查询走内存索引直查（10ms 级），任意正则仍可全扫（400ms 级），索引小（120MB/GB）且构建快
2. **查询与结果构建分离**——查询只收集命中偏移；预览文本在前端窗口拉取时按需生成，宽查询（百万命中）不拖慢
3. **分块并行 + 顺序读**——16MB 块多核并行，块边界对齐换行；候选行访问用顺序游标（4MB 缓冲复用），无随机 IO

## 构建与开发

前置：Go 1.25+、Node.js 18+、Wails CLI（`go install github.com/wailsapp/wails/v2/cmd/wails@latest`）

```bash
wails build              # 产出 build/bin/log-hunter.exe（约 12MB 单文件）
wails dev                # 开发模式（热更新）
go test ./internal/...   # 核心包单测
go run ./cmd/logscan-bench -size 1024   # 性能基准（生成 1GB 日志并计时）
go run ./tools/genicon   # 重新生成应用图标（build/appicon.png + icon.ico）
./release.ps1 -Version 0.0.1 # 发版打包（release/<版本>/ 下产出 zip，临时文件自动清理）
```

## 已知限制

- 单行超过 64KB 会被防御性截断（真实日志到不了这个量级；防异常行撑爆界面）
- GBK 文件的正则按 GBK 字节匹配，含 Unicode 范围类（如 `\x{4e00}`）的正则不适用 GBK 文件；高亮为 UTF-8 侧匹配，GBK 文件的中文正则可能只匹配不高亮
- 无时间戳的行（多行堆栈）不参与时间范围过滤（附属于上一条日志）；级别过滤同样只作用于有级别的行
- 结果上限 200 万条（防误用过宽条件耗尽内存，超限截断并提示）
- Windows 图标有系统缓存：换图标后若桌面快捷方式仍显示旧图，重建快捷方式或重启资源管理器
