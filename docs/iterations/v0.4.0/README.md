## 目标（为什么做）

AI 诊断定位质量被「证据截断」拖后腿：search 50 条 / follow 500 行截断后无任何续读手段（get_context 读的是物理行不是命中序列），get_line 号称读全文却同走 capSampleText 截 800B——超上限行模型没有任何手段读全。预防性能力评估定调：分析完整性优先于 token 经济性，上限只受模型窗口物理约束。

## 范围（做了什么，清单）

- search 上限 50→500 条 + offset 续读（命中序列可穷尽）
- follow 上限 500→1000 行 + offset 续读（链路尾部可续读）
- 命中计数分场景：无文本条件从索引精确计数（零成本）/ 有文本条件计数上限提到 10 万并提前终止（防大日志全扫等待）
- 行文本 800B→2048B；get_line 真正不截断（超长行读全通路修复）
- get_stack 200 行/64KB→500 行/256KB，新上限截断补提示
- 工具描述/截断提示/prompt 方法论同步更新

## 影响面

- 前端仅透传 offset 参数、展示提示文案，无组件改动
