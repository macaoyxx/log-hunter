## 目标（为什么做）
①多节点日志按「拖入顺序 + 行号」平铺拼接，与时间无关，交叉排查需人工来回切换文件；②时间范围筛选把无时间戳的行（异常堆栈/SQL 续行）全部排除，主行命中但上下文丢失；③TimePicker 改时分后值不生效（apply 链路只在点日期格时触发）。核心诉求：多个节点日志按时间顺序归并成单一时间线，无时间内容跟随主行不丢失，默认保持平铺、可选合并。

## 范围（做了什么，清单）
- **时间合并视图**：结果表状态栏「平铺 | 时间合并」视图开关，即时重排（后端对已有结果稳定排序，不重扫文件）；合并模式下新查询自动按合并序产出
- **向前继承锚点**（统一语义）：无时间行继承同文件上一条有时间行的时间戳——时间筛选按锚点判断去留；合并排序按锚点归位（稳定排序保证堆栈块紧贴主行不被其他节点行插散）
- **无时间文件**（整文件无时间格式，如纯 SQL dump）：合并视图命中置尾分节 + 提示；设时间条件时始终跳过（现状行为）+ 查询统计提示跳过数（QueryStats.skippedNoTime）
- **惰性预览分组读**：合并序下 FileID 不连续，GetResults/ExportResults 改为窗口内按 (FileID, Offset) 排序后分组顺序读（平铺序下为稳定 no-op）
- **TimePicker 修复**：时/分/秒输入框 @change 即 apply、「好」按钮 apply 后关闭、「+秒/−秒」切换后 apply；非法输入（非数字/越界）归一回退，防脏时间串进查询
- **README/LICENSE**：开头补「为什么用」核心卖点与常见文本工具类别差异对比（只写类别不点名产品）、底部补 License 节；Apache-2.0 附录版权占位符补全署名年份

## 影响面
- `QueryStats` 新增 `skippedNoTime` 字段，前端绑定随 wailsjs 再生成（已同步）

- 结果视图默认仍为平铺，不切换则交互零变化
