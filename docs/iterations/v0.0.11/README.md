## 目标（为什么做）
用户实际场景存在「zip 套 zip」日志包（外层收集包、内层按服务/日期再打包），旧版只解 1 层——嵌套 zip 是压缩二进制必含 NUL，被内容级二进制探测当二进制跳过。同时审查发现两个清理口子：进程崩溃/强杀时退出钩子不执行，`%TEMP%` 解压目录永久残留且无回收机制；删光某 zip 全部文件后去重登记不清，重拖同包被「已加载过」永久误挡。

## 范围（做了什么，清单）
- **嵌套 zip 递归解压**：按内容魔数（PK 头）识别内层 zip，不依赖扩展名；限 3 层（第 4 层提示「嵌套超过 3 层，跳过」）；显示名递归续接（如 `outer.zip/svc.zip/day.zip/c.log`）；每层独立临时子目录，随移除按目录引用计数隔离清理
- **zip 炸弹双闸**：解压总量 8GB 上限从每层各算收紧为整包累计（含内层 scratch 字节）；深度上限兜病态嵌套
- **解压残留启动回收**：清扫 `%TEMP%\log-hunter-unzip-*` 陈旧目录（修改时间 >1 小时 + 锁文件探针双护栏，多实例互不误删、幂等重试）；退出删除失败（杀毒占用）加 3 次有限重试
- **修复重拖误挡**：删光某 zip 全部文件后同步清去重登记，重拖同包可正常重新加载

## 影响面
无接口变更；外层 zip 的提示文案/显示名/进度行为与旧版一致（仅嵌套条目从「二进制，跳过」变为递归解出）。
